# 数据库事务基础

## 事务的 ACID 特性

数据库事务（Transaction）是一组数据库操作的逻辑单元，具有 ACID 四个特性：原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）和持久性（Durability）。原子性保证事务中的所有操作要么全部成功，要么全部回滚；一致性保证事务执行前后数据库处于一致状态。

## 隔离级别

数据库事务的隔离级别决定了并发事务之间的可见性。SQL 标准定义了四种隔离级别：读未提交（Read Uncommitted）、读已提交（Read Committed）、可重复读（Repeatable Read）和串行化（Serializable）。隔离级别越高，数据一致性越强，但并发性能越低。

读已提交是大多数数据库的默认隔离级别，它防止脏读（读取到未提交的数据），但允许不可重复读和幻读。可重复读防止不可重复读，但在某些数据库中仍可能出现幻读。串行化提供最强的一致性保证，但通过加锁或版本控制会显著降低并发性能。

## 乐观锁与悲观锁

乐观锁假设冲突很少发生，在提交时才检查数据是否被其他事务修改。通常通过版本号或时间戳实现：读取数据时获取版本号，提交时检查版本号是否变化，如果变化则回滚。乐观锁适合读多写少的场景。

悲观锁假设冲突经常发生，在读取数据时就加锁，阻止其他事务修改同一数据。悲观锁适合写竞争激烈的场景，但会降低并发性能。在 SQLAlchemy 中，可以使用 with_for_update 方法实现悲观锁。

## SQLAlchemy 事务管理

在 SQLAlchemy 中，事务通过 Session 对象管理。Session 在首次执行 SQL 时隐式开始一个事务，调用 commit 方法提交事务，调用 rollback 方法回滚事务。Session 还支持嵌套事务（SAVEPOINT），通过 begin_nested 方法创建保存点。

Session 的 autoflush 行为决定了何时将挂起的更改刷新到数据库。在默认的 autoflush=True 模式下，Session 会在执行查询前自动将挂起的更改刷新到数据库。这确保了查询能看到最新的数据状态，但也可能导致意外的 SQL 执行。

## 分布式事务

分布式事务涉及多个资源管理器（如多个数据库、消息队列），需要保证跨资源的原子性。两阶段提交（2PC）是经典的分布式事务协议：协调者先向所有参与者发送准备请求，所有参与者确认后协调者发送提交请求。两阶段提交保证原子性，但存在阻塞问题和单点故障风险。
