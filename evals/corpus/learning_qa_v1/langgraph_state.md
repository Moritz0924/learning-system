# LangGraph 状态管理

## 什么是 LangGraph

LangGraph 是一个用于构建基于状态图的 Agent 应用的框架。它允许开发者将复杂的多步骤工作流建模为有向图，图中的节点代表处理步骤，边代表状态流转方向。LangGraph 的核心是状态管理机制，每个节点接收当前状态并返回状态更新。

## 状态对象

LangGraph 使用 TypedDict 或 Pydantic 模型定义状态对象。状态对象描述了在图执行过程中需要在不同节点之间传递的所有数据。每个节点函数接收当前状态作为输入，并返回一个包含更新字段的字典，LangGraph 会将这些更新合并到状态中。

状态对象的字段可以包括：用户消息、检索到的上下文、生成的回答、评估结果、工作流动作列表等。通过明确定义状态结构，可以确保不同节点之间的数据传递是类型安全的。

## Checkpointer 与线程恢复

LangGraph 通过 Checkpointer 机制实现状态的持久化和线程恢复。Checkpointer 会将每个节点执行后的状态快照保存到存储后端（如内存、PostgreSQL）。当使用相同的 thread_id 再次调用图时，LangGraph 可以从 Checkpointer 恢复此前的状态，实现多轮对话的上下文连续性。

PostgreSQL Checkpointer 是生产环境中推荐的持久化方案，它可以将状态快照可靠地存储在关系数据库中，并支持跨进程、跨实例的状态恢复。这对于需要水平扩展的应用尤为重要。

## 条件路由

LangGraph 支持条件路由，即根据当前状态动态决定下一个执行的节点。条件路由通过条件边函数实现：函数接收当前状态，返回目标节点名称。这使得工作流可以根据中间结果（如评估分数、检索状态）自适应地调整执行路径。

例如，在一个辅导系统中，可以根据触发类型（聊天、评估提交、任务完成）将请求路由到不同的处理节点。这种灵活性使得 LangGraph 适合构建复杂的自适应工作流。

## 不可序列化对象处理

在 LangGraph 中，进入 Checkpoint 的状态必须是可序列化的。这意味着 SQLAlchemy Session、HTTP Client、文件句柄等不可序列化对象不应直接放入状态中。正确的做法是将这些对象作为依赖项注入，而不是放入图的状态。持久化的 State 与运行期的 Context 需要分离，运行期对象在每次执行时重新创建。
